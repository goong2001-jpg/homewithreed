# 내 자산관리 (asset-tracker)

전세보증금·대출·예적금·투자를 **잔액 기준**으로 관리하는 개인 자산관리 앱입니다.
`couple-budget`이 매달 들어오고 나가는 **흐름**을 본다면, 이 앱은 **지금 얼마를 갖고 있고 얼마를 빚졌는지**를 봅니다.

배포 주소: `https://<계정>.github.io/homewithreed/asset-tracker/`

---

## 화면

| 탭 | 하는 일 |
|---|---|
| 📊 **한눈에** | 순자산 · 자산 구성 · 매달 나가는 돈 · 다가오는 만기 · 자산/대출 목록 |
| 💰 **자산** | 분류별로 자산을 넣고 고치기. 분류 자체도 추가·수정·삭제 |
| 💳 **나가는돈** | 대출(남은 원금·월 상환액·진행률)과 고정비 |
| ⚙️ **설정** | 백업 내보내기/불러오기, 지운 항목 되살리기, 전체 초기화 |

목록의 **아무 줄이나 누르면** 아래에서 편집 시트가 올라옵니다. 따로 '수정' 버튼을 찾을 필요가 없습니다.

```
순자산 = 총자산 − 남은 대출 원금
매달 나가는 돈 = 대출 월 상환액 + 고정비
```

### 내 몫 — 걸린 대출을 뺀 진짜 내 돈

전세보증금 9,900만원을 대출 6,600만원 + 내 돈 3,300만원으로 마련했다면,
보증금 전액이 자산인 건 맞지만 **그게 다 내 돈은 아닙니다.**

대출 편집의 **어떤 자산 때문에 빌렸나요**(`Loan.linkedAssetId`)로 연결해두면,
자산 목록에 평가액과 함께 **내 몫 3,300만원**이 같이 뜹니다.

```
내 몫 = 평가액 − 연결된 대출의 남은 원금   (음수면 0)
```

연결하지 않은 대출(신용대출 등)은 특정 자산의 몫을 깎지 않고 순자산에서만 빠집니다.
중도상환으로 직접 적은 남은 원금도 그대로 반영됩니다.

### 언제 쓸 수 있나 — 유동성 3단계

보증금 9,900만원과 통장 300만원을 똑같이 '자산'으로만 세면
"지금 당장 쓸 수 있는 돈이 얼마인가"에 답할 수 없습니다.

| 단계 | 뜻 | 기본으로 들어가는 분류 |
|---|---|---|
| 💵 지금 바로 | 통장 잔고, 파킹통장, 현금 | 현금 |
| ⏳ 며칠이면 | 주식·펀드(팔면 2~3일), 중도해지 가능한 예적금 | 예적금·청약, 투자 |
| 🔒 묶여 있음 | 전세보증금, 부동산, 청약, 퇴직연금 | 보증금·부동산, 기타 |

`Asset.liquidity`가 `null`이면 **분류 기본값**(`DEFAULT_LIQUIDITY`)을 따릅니다.
사용자가 만든 분류는 `'묶임'`으로 떨어집니다 — 가용자금을 부풀리는 쪽으로 틀리면 안 되니까요.

홈의 **지금 쓸 수 있는 돈**은 `'즉시'` 자산의 **내 몫** 합계입니다.
주식담보대출처럼 유동자산에 빚이 걸린 경우까지 정직해집니다.

단계 줄을 누르면 **그 안에 든 자산이 펼쳐집니다**(한 번에 한 단계).
대출이 걸려 평가액과 내 몫이 다를 때는 `평가액 8,766만원 · 대출 6,613만원`처럼 근거를 같이 보여줍니다.
펼친 자산을 누르면 바로 편집 시트가 열립니다.

## 대출 계산

`src/utils/loan.ts` 가 전부 계산합니다. 월이율 `i = 연이율 ÷ 100 ÷ 12`, 상환 개월 `n = 총기간 − 거치기간`.

| 상환 방식 | 매달 내는 돈 | 남은 원금 |
|---|---|---|
| **원리금균등** | `A = P·i ÷ (1 − (1+i)⁻ⁿ)` — 매달 같음 | `P·((1+i)ⁿ − (1+i)ʲ) ÷ ((1+i)ⁿ − 1)` |
| **원금균등** | 원금 `P/n` 고정 + 잔액×i — 갈수록 줄어듦 | `P − (P/n)·j` |
| **만기일시** | 이자 `P·i` 만 | 만기까지 `P` 그대로 |

**거치기간**은 원금을 그대로 두고 이자만 내는 기간입니다(전세자금대출에 흔함).
거치 중에는 남은 원금이 줄지 않고 월 상환액이 `P·i` 로 고정됩니다.

만기일시는 원금이 안 줄어서 '원금 상환률' 막대가 늘 비어 있으므로, 화면에서는 대신 **기간 경과율**을 보여줍니다.

무이자(`i = 0`)면 위 공식이 0으로 나눠지므로 따로 분기합니다.

### 중도상환했다면 — 직접 적기

중도상환을 하면 위 계산이 실제와 어긋납니다. 최초 원금을 낮춰봐야 거기서 또 갚은 만큼 빠져서 더 틀어집니다.
그래서 대출 편집 화면의 **지금 남은 원금 → [직접 적을게]** 로 은행 앱에 찍힌 잔액을 그대로 넣을 수 있습니다.

- `manualRemaining` 이 있으면 `loanStatus()` 는 계산을 통째로 건너뜁니다
- **적은 값은 저절로 줄지 않습니다.** 대신 `manualAsOf`(적은 날짜)를 카드에 같이 띄워 낡았는지 보이게 합니다
- 월 상환액도 적을 수 있습니다. 비우면 남은 원금을 남은 기간에 나눠 갚는 걸로 계산합니다
- 이때 '만기까지 총 이자'는 성립하지 않으므로 **앞으로 낼 이자**로 바뀝니다.
  계약 기간이 아니라 `payoffMonths(잔액, 월이율, 상환액)` — 실제 상환 속도로 계산합니다.
  상환액이 이자에도 못 미치면 영원히 안 끝나므로 `—` 로 표시합니다

## 데이터는 어디에

**이 브라우저의 localStorage에만 있습니다.** 서버로 아무것도 보내지 않습니다.

그래서 브라우저 데이터를 지우거나 폰을 바꾸면 **그대로 사라집니다.**
가끔 **설정 → 백업 파일로 내보내기**를 눌러 JSON 파일을 받아두세요. 이게 유일한 방어선입니다.

불러오기는 지금 기록 위에 **합칩니다**(`utils/merge.ts` 의 `mergeById`).
항목마다 `id` 와 `updatedAt` 이 있고 삭제도 툼스톤(`deleted: true`)으로 남기 때문에,
백업을 얹어도 지운 항목이 되살아나지 않고 더 최근에 고친 쪽이 남습니다.

폰에서 **공유 → 홈 화면에 추가**를 하면 앱 아이콘으로 열리고, 저장한 기록도 더 오래 남습니다.

## 개발

```bash
cd asset-tracker
npm ci
npm start                      # http://localhost:3000
npm test -- --watchAll=false   # loan / summary / format
npm run build
```

### 구조

```
src/
  App.tsx              # 탭 라우팅 + summarize()를 돌리는 useMemo 하나
  types/index.ts       # 도메인 타입과 상수 전부
  hooks/useAssets.ts   # localStorage CRUD (삭제는 툼스톤)
  components/          # 화면과 편집 시트. 전부 인라인 style
  utils/
    loan.ts    + .test # 대출 상환 계산
    summary.ts + .test # 순자산·구성·만기 집계
    format.ts  + .test # 원/억/만원, D-day 표기
    date.ts            # 날짜 계산 (지역시각 기준)
    merge.ts, storage.ts, backup.ts, id.ts
```

**돈 계산은 반드시 `utils/` 의 순수 함수에 두고 `.test.ts` 를 같이 씁니다.**
'오늘'은 항상 인자로 주입해서 테스트가 시계에 의존하지 않게 합니다 — `couple-budget/src/utils/budget.ts` 와 같은 관행입니다.

컴포넌트는 계산하지 않습니다. `App.tsx` 의 `useMemo` 가 `summarize()` 를 한 번 돌리고 결과를 내려줍니다.

### 스타일

Tailwind도 CSS 모듈도 쓰지 않습니다. 전부 인라인 `style={{}}` 이고,
공유하는 값(카드·색·행·버튼)은 `src/components/ui.ts` 에 모여 있습니다.
`index.css` 는 리셋과 시트 애니메이션 두 개뿐입니다.
