# 집무전기 (walkie-talkie)

폰 마이크와 스피커만으로 쓰는 **PTT(누르고 말하기) 무전기** PWA입니다.
같은 **채널 번호 4자리**를 넣은 사람끼리 최대 6명이 연결되고, 큰 버튼을 누르는 동안만 목소리가 나갑니다.

* 서버 없음 — 음성은 브라우저끼리 직접(WebRTC P2P) 오갑니다. 통화료·서버비 0원.
* 설치 없음 — 주소만 열면 됩니다. 홈 화면에 추가하면 앱처럼 씁니다.
* 가입 없음 — 이름과 채널 번호만.

## 쓰는 법

1. 두 사람 다 같은 주소를 엽니다.
2. 이름과 **똑같은 채널 번호 4자리**를 넣고 `채널 열기`.
3. 마이크 권한 허용 → 상대가 들어오면 상단에 이름이 뜹니다.
4. 가운데 큰 버튼을 **누르고 있는 동안** 말이 전달됩니다. (PC는 스페이스바)

옵션 두 가지가 있습니다.

| 옵션 | 설명 |
|---|---|
| 손 떼도 계속 송신 | 버튼을 토글로 바꿉니다. 운전 중처럼 손을 못 쓸 때. |
| 말하는 동안 상대 소리 줄이기 | 스피커폰 하울링을 막습니다. 기본 켜짐. |

## 아는 한계 (중요)

* **백그라운드 수신이 안 됩니다.** 브라우저를 닫거나 다른 앱으로 나가면, 특히 아이폰은 화면을 끄면
  연결이 끊깁니다. 화면을 켜둔 채로 쓰는 용도입니다. (화면 자동 꺼짐은 앱이 막아줍니다.)
  진짜 "폰이 꺼져 있어도 삐- 하고 상대 목소리가 나오는" 무전기는 iOS `PushToTalk` 프레임워크가 필요하고,
  이건 앱스토어 네이티브 앱 + Apple 승인(VoIP entitlement)이 있어야 합니다.
* **스피커/이어폰 전환을 앱이 고를 수 없습니다.** 웹은 출력 장치를 강제하지 못합니다.
  이어폰이 꽂혀 있으면 이어폰으로, 아니면 스피커로 나갑니다.
* **채널 번호를 아는 사람은 누구나 들어옵니다.** 암호가 아닙니다. 통신 자체는 WebRTC라 암호화되지만
  방 번호는 비밀번호가 아니라는 뜻입니다. 남들이 안 쓸 번호를 쓰세요.
* **가끔 연결이 안 될 수 있습니다.** 이동통신망끼리는 직접 연결이 막혀 중계(TURN) 서버를 타는데,
  지금은 무료 공개 서버를 씁니다. 자주 끊기면 `app.js`의 `ICE` 값을 유료/자체 TURN으로 바꾸세요.

## 구조

빌드가 필요 없는 정적 파일입니다.

```
index.html   화면
app.js       PTT·연결 로직 (PeerJS CDN 사용)
style.css    스타일
sw.js        오프라인 껍데기 캐시
manifest.json / icon*  PWA 설치용
```

연결 방식:

1. 채널마다 **허브 자리**(`hwr-wt-<채널>-hub`)가 하나 있습니다. 먼저 들어온 사람이 차지합니다.
2. 허브는 **참가자 명단만** 관리합니다. 통화는 하지 않습니다.
3. 나머지는 허브에 이름을 알리고 명단을 받아, **명단에 실제로 있는 사람하고만** 직접 연결합니다.
4. 허브가 나가면 남은 사람 중 하나가 자동으로 이어받습니다. 이미 이어진 통화는 그대로 유지됩니다.

> 첫 버전은 자리 6개를 5초마다 전부 두드려 보는 방식이었는데, 빈 자리에도 계속 연결을 걸어
> 폰 브라우저의 동시 연결 한도를 잡아먹고 **진짜 연결까지 실패**시켰습니다. 그래서 위 구조로 바꿨습니다.

## 연결이 안 될 때

무전 화면 맨 아래 **`연결 진단 기록`**을 펴면 어느 단계에서 막혔는지 보입니다.

| 기록에 나오는 말 | 뜻 | 대응 |
|---|---|---|
| `브로커 접속됨` 이 안 뜸 | 시그널링 서버(PeerJS 공개 브로커)에 못 붙음 | 잠시 후 재시도 |
| `내가 허브가 되었습니다` 가 양쪽 다 뜸 | 채널 번호가 서로 다름 | 번호 다시 확인 |
| `연결 시도` 만 반복되고 `소리 연결됨` 이 없음 | 상대까지 길이 안 뚫림 | 같은 와이파이에서 재시도 |
| `ICE(...): failed` | 직접 연결도 중계도 막힘 | 전용 TURN 서버 필요 |
| `자동 재생 차단` | 소리 권한 | 화면의 `소리 켜기` 버튼 누르기 |

### 한쪽 목소리만 안 갈 때

무전 화면의 **`내 목소리` 막대**와 그 아래 **`상대이름 ↑보냄 ↓받는중`** 표시를 보면 어느 쪽이
끊겼는지 바로 나옵니다.

| 보이는 것 | 뜻 |
|---|---|
| 말하는데 `내 목소리` 막대가 안 움직임 | 내 마이크가 안 잡힘 (다른 앱이 마이크 점유 중이거나 권한 문제) |
| 막대는 움직이는데 상대에게 안 들림 | 내 → 상대 방향만 막힘. 상대 표시가 `↓안옴` 이면 확실 |
| `↓안옴` 이 빨갛게 계속 남음 | 그 상대로부터 소리가 한 번도 안 왔음 |

PTT 는 마이크 트랙을 껐다 켜는 대신 **소리 크기를 여닫는 방식**입니다. 트랙을 끈 채로 연결을
맺으면 한쪽 방향이 '받기 전용'으로 굳어버리는 폰이 있어서(주로 사파리) 그렇게 만들었습니다.

`기록 복사` 버튼으로 그대로 복사해 보낼 수 있습니다.

## 로컬에서 보기

마이크는 `https` 또는 `localhost`에서만 열립니다.

```bash
cd walkie-talkie
npx serve .        # 또는 python3 -m http.server 8000
```

폰끼리 시험하려면 GitHub Pages에 올라간 https 주소로 접속하세요.

## 자동 테스트

가짜 브로커(`test/fakepeer.js`)를 끼워 넣고 탭 두 개를 띄워, 입장 → 서로 인식 → PTT 송신 →
퇴장까지를 확인합니다. 실제 인터넷 연결 없이 로직만 검증합니다.

```bash
cd walkie-talkie
npx http-server -p 8137 -s .          # 다른 터미널에서
npx playwright install chromium       # 처음 한 번
node test/smoke.js
```

확인하는 것: 허브 선점, 명단 전파, 이름 교환, 송신 표시 전파, 퇴장 처리,
**허브가 나갔을 때 다른 사람이 이어받고 새 참가자가 여전히 들어올 수 있는지**, 콘솔 오류 없음.
