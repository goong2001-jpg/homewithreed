# 우리집 하루수입 가계부 (couple-budget)

월 수입을 **그 달의 실제 일수로 나눠 "하루 수입"으로 환산**해서 보여주는 부부 가계부입니다.
돼지저금통이 채워진 정도로 지금 형편을 한눈에 볼 수 있고, 지출을 입력하면 저금통이 줄어듭니다.

배포 주소: `https://<계정>.github.io/homewithreed/couple-budget/`

---

## 어떻게 계산하나요

```
하루 수입 = (월 총수입 − 월 고정지출) ÷ 그 달의 실제 일수
현재 여유돈 = (경과일수 × 하루 수입) − 이달 누적 지출
```

예를 들어 수입이 320만원이고 고정지출이 없다면

| 달 | 일수 | 하루 수입 |
|---|---|---|
| 6월 | 30일 | 106,666원 |
| 7월 | 31일 | 103,225원 |
| 2월 (평년) | 28일 | 114,285원 |

**같은 수입이라도 달마다 하루 금액이 조금씩 다릅니다.** 달력 기준으로 나누기 때문이고, 의도된 동작입니다.

월세 100만원을 고정지출로 등록하면 `(320만 − 100만) ÷ 31일 = 하루 70,967원`이 됩니다.
고정지출은 하루 수입을 계산할 때 **미리 빠지므로**, 저금통에 남은 돈은 마음 편히 써도 되는 돈입니다.

### 저금통이 뜻하는 것

- **채워진 높이** = 이달 남은 예산 ÷ 이달 쓸 수 있는 돈. 1일에 가득 차 있고 쓸수록 줄어듭니다.
- **점선** = 오늘까지의 목표선. 물높이가 점선보다 **위에 있으면 잘 아끼고 있는 것**입니다.
- **색** = 지금 여유돈 상태. 🟢 여유 / 🟠 하루치 미만 / 🔴 예산 초과(저금통에 금이 갑니다).

경과일수는 이번 달이면 오늘 날짜, 지난 달이면 그 달 전체(최종 결산), 다음 달이면 0(계획 미리보기)입니다.

## 동기화 없이 그냥 쓰기

아무것도 설정하지 않아도 앱은 완전히 동작합니다. 다만 **기록이 그 폰의 브라우저에만 저장**되므로

- 브라우저 데이터를 지우면 기록도 사라집니다
- 배우자 폰에서는 보이지 않습니다

가끔 **설정 → 데이터 → Excel 내보내기**로 백업해 두세요.

---

## 둘이 같이 쓰려면 (Firebase 무료 설정, 약 10분)

한쪽에서 지출을 입력하면 상대 폰에도 1~2초 안에 반영됩니다. 로그인·회원가입은 없고, **우리집 코드** 하나만 서로 맞추면 됩니다. 처음 한 번만 설정하면 끝입니다.

1. **console.firebase.google.com** 접속 → 구글 로그인
2. **프로젝트 만들기** → 이름은 아무거나 (예: `우리집가계부`) → Google 애널리틱스는 **사용 안 함** → 만들기
3. 프로젝트 개요 화면에서 **웹 아이콘 `</>`** 클릭 → 앱 닉네임 입력 → **앱 등록** (Firebase Hosting은 체크하지 않음)
4. 화면에 나오는 코드 중 `const firebaseConfig = { … };` 의 **중괄호 부분을 통째로 복사**
5. 왼쪽 메뉴 **빌드 → Firestore Database** → **데이터베이스 만들기** → 위치는 **asia-northeast3 (서울)** → **프로덕션 모드로 시작** → 만들기
6. Firestore 화면 위쪽 **규칙** 탭 → 기존 내용을 전부 지우고 아래 규칙을 붙여넣은 뒤 **게시**
7. 가계부 앱에서 **설정 탭 → 둘이서 같이 쓰기** → **새 코드 만들기** → 4번에서 복사한 설정을 붙여넣고 → **저장하고 연결하기**
8. **지금까지 기록 클라우드로 올리기** 를 눌러 이 폰의 기록을 올립니다
9. 배우자 폰에서 같은 주소를 열고 → 설정 → **같은 코드**와 **같은 설정**을 입력 → 저장
10. 한쪽에서 지출을 입력했을 때 다른 쪽 저금통이 줄어들면 성공입니다

### 6번에서 붙여넣을 보안 규칙

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /rooms/{roomCode}/{document=**} {
      allow read, write: if roomCode.size() >= 12;
    }
  }
}
```

## ⚠️ 꼭 알아둘 점 — 우리집 코드가 곧 비밀번호입니다

로그인 없이 쓰는 구조라서, **코드를 아는 사람은 누구나 우리 가계부를 보고 고칠 수 있습니다.**
위 규칙의 `roomCode.size() >= 12`는 `test`, `1234` 같은 짧은 코드를 찍어보는 시도만 막아 줍니다.
제대로 된 접근 제어가 아니라는 점을 분명히 알아두세요.

그래서 이렇게 대비합니다.

- 앱이 **16자 랜덤 코드**를 만들어 줍니다 (예: `k7fq-2mx9-tv58-hd3p`). 약 80비트라 찍어서 맞히는 건 현실적으로 불가능합니다.
- **직접 짧은 코드를 넣지 마세요.** 12자 미만은 앱에서 막습니다.
- 코드를 **카톡·메일로 보내지 말고** 배우자 폰에 직접 입력해 주세요.
- 코드가 새어나갔다고 생각되면 **새 코드를 만들고** 다시 **클라우드로 올리기**를 누르세요. 이전 방은 버려집니다.
- 더 확실하게 잠그고 싶으면 나중에 Firebase **익명 인증**을 켜고 규칙에 `request.auth != null && request.auth.uid in resource.data.members` 를 추가하는 방식으로 올릴 수 있습니다. 초대 절차가 생기므로 지금은 넣지 않았습니다.

담기는 정보는 금액과 짧은 메모 정도라 민감도가 높지는 않지만, 그래도 남에게 보일 이유는 없습니다.

## 자주 겪는 문제

| 증상 | 원인과 해결 |
|---|---|
| `접근이 거부되었어요` | 6번 보안 규칙을 **게시**하지 않았거나, 코드가 12자 미만입니다 |
| `Firebase 프로젝트를 찾지 못했어요` | 5번 Firestore 데이터베이스를 만들지 않았습니다 |
| `설정을 읽지 못했어요` | 4번에서 복사할 때 일부가 빠졌습니다. `{` 부터 `}` 까지 통째로 다시 복사하세요 |
| 상대 폰에 안 보임 | 두 폰의 **우리집 코드가 정확히 같은지** 확인하세요 (대소문자·하이픈 포함) |
| 비행기 모드에서 입력함 | 그대로 저장됩니다. 인터넷이 연결되면 자동으로 전송됩니다 |
| 새 폰에서 과거 내역이 안 보임 | 내역 탭 맨 아래 **지난 데이터 모두 불러오기**를 누르세요 (평소엔 보고 있는 달만 받아 옵니다) |

## 개발

```bash
npm install
npm start                        # http://localhost:3000
npm test -- --watchAll=false     # 계산·병합 로직 단위 테스트
npm run build                    # 배포 빌드
```

- CRA(react-scripts 5) + React 19 + TypeScript. 형제 앱들과 같은 구성입니다.
- 상태는 localStorage 우선. 화면 갱신이 네트워크를 기다리는 일은 없습니다.
- `firebase`와 `xlsx`는 **동적 import**로 별도 chunk로 분리됩니다. 동기화를 안 쓰면 firebase를 내려받지 않습니다.
- 돈 계산은 전부 `src/utils/budget.ts` 의 순수 함수이고 `budget.test.ts` 가 검증합니다. 테스트는 날짜를 주입해 시스템 시계에 의존하지 않습니다.
- `homepage` 는 `/homewithreed/couple-budget/` 입니다. 배포 경로가 바뀌면 이 값을 함께 고쳐야 합니다.

### 동기화 구조

| 파일 | 역할 |
|---|---|
| `src/sync/types.ts` | `SyncClient` 계약. firebase import 없음 (메인 번들 보호) |
| `src/sync/syncClient.ts` | firebase를 만지는 유일한 파일. 전부 동적 import |
| `src/hooks/useSync.ts` | 연결 수명 관리, 보고 있는 달만 구독 |
| `src/hooks/useLedger.ts` | 단일 진실 공급원. 로컬 저장 후 클라우드로 던지기만 함 |
| `src/utils/merge.ts` | id 기준 last-write-wins 병합 |

클라우드 구조는 `rooms/{코드}/{incomes,fixedExpenses,expenses}/{문서}` 입니다.
지출을 서브컬렉션으로 둔 이유는 문서 1 MiB 한도를 피하고, 두 사람이 서로 다른 문서를 써서 쓰기 충돌이 나지 않게 하기 위함입니다.
`Expense.month` 를 비정규화해 둔 덕분에 복합 색인을 따로 배포하지 않아도 월별 조회가 됩니다.

삭제는 하드 삭제가 아니라 `deleted: true` 툼스톤입니다. 구독이 월 단위라 "이 스냅샷에 없다"가 삭제인지 다른 달인지 구분되지 않기 때문에, 삭제도 하나의 수정으로 흘려보내야 로컬 사본과 안전하게 합쳐집니다.
