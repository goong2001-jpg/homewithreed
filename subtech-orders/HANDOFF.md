## 2. 꼭 지킬 규칙

1. **재고앱을 건드리지 않는다.** `subtech-inventory/` 폴더, 브랜치 `claude/spreadsheet-accessibility-opmsi3`, 워크플로 `deploy-subtech.yml` 수정 금지.
2. **시트는 `주문`, `주문_거래처`, `주문_송장기록`, `주문_설정`, `주문_출하기록`, `주문_삭제기록`, `주문_학습` 탭만 쓴다.** `품목마스터`는 읽기만, `거래로그`·`위치도` 등은 읽지도 쓰지도 않는다. (`Code.gs`의 `sheet_()`가 `OWN` 목록 밖의 탭을 거절함 · 테스트가 검사) 재고 연결(3단계)로 `거래로그`에 쓰게 될 때는 **사용자 승인을 따로 받는다.**
3. **새 배포 만들지 않기.** 처음 한 번(DEPLOY.md 4번) 말고는 "배포 > 새 배포" 금지 — 주소가 바뀜.
4. **버전 짝 맞추기.** `Code.gs`의 `APP_VERSION`과 `Index.html`의 `HTML_VERSION`을 같이 올린다. 다르면 워크플로가 막고 앱이 경고를 띄움.
5. **엑셀 양식은 바꾸지 않는다.** `Out.html`의 `CJ_H`·`KD_H`·`DS_H`·`RP_H`(머리줄)와 열 순서는 사무실이 쓰던 파일 그대로 (사용자 요청: "형식은 가급적 바꾸지마").
6. **실제 고객 정보를 저장소에 올리지 않는다.** 카톡 원문·엑셀 원본·주소록은 커밋 금지. 테스트 견본은 지어낸 이름·전화·주소만. (`dev/.gitignore`가 `*.xlsx`, `data*.json`, `out/` 제외)
7. **주문 탭 열 순서 바꾸지 않기** (`OH`/`OK_`). 새 열은 맨 뒤에 덧붙인다. 업체가 취소한 실제 주문은 `상태=취소`로 남기고, 잘못 넣은 주문만 **삭제**(v2, `주문_삭제기록`에 30일 보관 후 자동 정리).
8. **`Index.html` 안에 `<` + `?` 를 붙여 쓰지 않는다** (끼워넣기 3줄 제외). Apps Script가 서버 코드로 읽어 앱이 안 열림. 테스트가 검사.
9. **새 권한(스코프)이 필요한 서비스(UrlFetchApp·DriveApp 등)를 넣지 않는다** — 웹앱이 재승인 전까지 멈춤. 지금은 스프레드시트 권한만.
10. 코드는 GitHub에서만 고친다 · 비밀값은 Secrets에만 · PR은 요청할 때만 · 푸시 후 배포 성공 확인까지가 작업 끝.
11. 변경 이력은 자동 기록(`CHANGELOG.md` 손대지 않기). 커밋 메시지 `vNN: 무엇을` + `- ` 목록. 봇 커밋이 생기므로 작업 시작·푸시 전에 `git pull --rebase origin ccr-45fa06b9-ax86xs`.
12. 사용자 응답은 **한국어, 짧게**. 결정이 필요하면 추천안을 먼저.

### 핵심 흐름
- **나눈 결과 쌓기** (v8, 실무자 요청): `나누기`를 누를 때마다 결과가 **아래에 추가**되고 붙여넣기 칸은 비워짐 → 카톡을 하나씩 붙여넣고 나누기 반복 → 한 번에 저장. 같은 원문은 다시 안 넣음. 저장 전 결과는 브라우저에 보관(`so-drafts`)해서 새로고침해도 남음.
- **붙여넣기** → `OP.splitMessages`(폰 내보내기 `2026년 …, 이름 : ` / PC 복사 `[이름] [오전 11:17] ` / 형식 없으면 1건) → 메시지마다 `OP.parseOrder` → 품목이 하나라도 있으면 발주로 봄 → `enrich()`가 주소록으로 빈 칸 채움 → 미리보기에서 고치고 저장. 거래처가 없는 건 기본 체크 해제.
- **배송 판단** `shipParse`: 대신 > 경동 > 직납 > 직접수령(방문) > 퀵 > 택배(=CJ) > 화물(경동/대신 선택 필요). `shipLabel`이 출하서 표기를 만듦 (택배선불 청구 / 경동택배선불 / 대신화물 / 직납 …).
- **직송 건**: 받는분 이름+주소가 따로 있고 거래처가 주소록에 있으면 보내는분 = 거래처 (CJ 파일의 와이코퍼레이션·부경테크 방식).
- **송장**: 운송별 대기·미출력 주문 → 박스 입력(크기별 여러 줄 = 엑셀에서도 여러 줄) → 엑셀/복사 → `markPrinted`(박스 저장 + 송장기록 추가).
- **박스 추천** `OP.suggest`: ①품목·수량이 똑같은 옛 주문 → 그대로 ②없으면 품목별 "박스 한 개에 담은 양"(90% 지점)으로 계산. 2025.06~ CJ 기록으로 확인했을 때 크기+수 일치 약 76%, 박스 수 일치 약 86%, 추천 없음 약 6% (앞 85%로 배우고 뒤 15%로 확인). **참고용** — 화면에 "추천 — 확인하세요" 표시.
- **출하서** `closeDay`: 체크한 주문을 출고완료(출고일=그 날짜)로 바꾸고, 그 날 출고완료 전부 + 대기 전부를 `주문_출하기록`에 저장 → 화면이 `OUT.report`로 엑셀 생성. 같은 날 다시 마감하면 그 날짜 줄만 갱신. 부자재(센서·파워코드 등, `OP.isAcc`)는 "50개"처럼 글자로 쓰고 합계에서 뺌 (원래 양식과 같음).
- **출고 기록** `shipOrder` (v2): 주문 카드·출하서의 `출고` → 날짜(오늘·어제·달력) + 품목별 실제 수량. 덜 나가면 사유 필수(자재부족·업체요청·생산지연·기타), 잔량은 `대기로 남김`(새 주문 `원ID-r1`, 출고예정 "준비되면", 적요 "잔량 (사유)") 또는 `안 보냄`. 원래 주문은 나간 만큼으로 바뀌고 출고완료. 출하서 적요에 `주문 120 중 60 출고 (자재부족)`. 출하서 체크박스 = 다 나감(그날 날짜).
- **주문 목록** (v2): 대기는 출고 예정으로 묶음(오늘 / 내일 / 이번 주 / 다음 주 이후 / 날짜 미정). `고르기`로 여러 건 삭제·취소. 주문 창 출고 예정에 달력.
- **송장 화면** (v2): 맨 위 오늘 출력 수량(앱 기준, 참고용)·`카톡 보고 복사`("택배 N건 / 경동 N건 / 대신 N건")·`오늘 뽑은 ○○ 전체 받기`(경동·대신은 출발 전에 이걸로 한 번에). 카드에 `송장출력 ✓ 시각`. CJ 당일 목록은 대한통운 프로그램에서도 받을 수 있어 앱에선 회차 기록을 따로 안 만듦(실무자 의견).
- **하루 마감 파일** (v3): 출하서 화면 `마감하고 하루 파일 받기` → `OUT.day` → 엑셀 1개, 탭 `출하서`(출고현황 양식) · `CJ`/`경동`/`대신`(각 양식 그대로, 그날 나간 것·저장된 박스) · `직납·방문 등` · `미출고`. 그날 없는 운송 탭은 생략. 지난 날짜는 아래 목록을 눌러 다시 받음.
- **월 파일** (v3): 출하서 화면 `월 파일 받기`(달 고르기) → `API.monthData`(그 달 출고완료 주문 전부 + 마감한 날의 대기 목록) → `OUT.month` → 탭 `거래처별`(건수·출고일 수·제품/부자재 수량·명세서·계산서) · `품목별` · `출고목록`(품목 한 줄씩, 주문 수량·사유) + 날짜별 출하서 탭(최근 날짜 먼저, `11월.xlsx`와 같은 모양). 마감 안 한 날도 출고 기록이 있으면 탭이 생김(대기 목록은 비어 있음).
- **받는 곳·보내는분** (v3): 주문 창 `받는 곳`에 **이 거래처에 최근 보낸 곳**(boot의 `addrHist`: 주문 탭 전체에서 거래처별 최근 5개, 저장할 때 화면에서도 갱신) · 주소록에서 고르기 · 새 주소면 `주소록에 저장` 체크(입력하는 즉시 보임). `보내는분`은 써브텍 / 지난번(주소록의 보내는분) / 최근 주문에 쓴 보내는분 / 거래처 이름 / 직접 입력. 송장 카드의 `받는 곳 · 보내는분 고치기`가 주문 창을 그 부분으로 열어 줌.
- **옵션 줄 펼치기** (v4, `OP.expandItem`, 사용자 결정 11-18): 모델명(영문+숫자로 시작) 뒤나 다음 줄에 옵션 단어(색상·종류·조절기·온도센서·파워코드·리모컨·실버/화이트/블랙·무센서 등)가 있으면 →
  모델 = 주문 수량 그대로, **온도센서·파워코드·리모컨 = 같은 수량의 품목 줄**(조절기 줄의 센서 칸은 X — 기존 출하서 "H7 X 50 / 건식센서 30개" 방식), 조절기만·무센서 = 센서 X, 색상·"리모컨 없음" = 품목 메모, `C485`·`7단계`·`4kw`처럼 숫자 있는 규격 = 품목명에 남김, **처음 보는 단어 = 메모 + 미리보기 카드에서 "따로 품목으로 / 메모로 두기" 물어보기**(답은 `주문_학습` opt).
  옵션 단어가 없는 일반 발주(`H10 7단계 X 6 스티커있음`)는 그대로. `H5R 실버 (리모컨포함)-1` 처럼 괄호·옵션 뒤 `-수량`도 인식.
- **품목명 학습** (v4): 나눈 결과(초안)에서 품목명을 고치면 "원래 → 고친 이름"을 **그 거래처 기준**으로 기억(`주문_학습` name) → 다음 붙여넣기부터 자동. 예: (와이코퍼레이션) 온도센서 → 몰딩센서 2M.
- **배송 메시지** (v4): 문 앞·부재·경비실·택배함·택배실·파손·던지지·배송 전 연락 등은 어디서든, "~주세요/주시고/마세요/바랍니다/조치"는 받는분·전화·주소 바로 뒤일 때만 배송 메시지로. 출고·계산서·박스·동봉·포장·카다로그·택배(배송방법) 같은 말이 있으면 적요에 남김(포장 지시 구분).
- **품목마스터에 없음** (v4): 대기 주문 카드에 품목마스터 품명과 안 맞는 모델명을 회색 표시(경고만, 송장 막지 않음).
- **나누기 고칠 때 점검법**: 드라이브 `써브텍 9 카카오톡 대화`를 스크래치에 받아 고치기 전/후 Parse.html 로 3개월치를 각각 나눠 비교(품목·배송 메시지·주소·적요가 바뀐 경우를 종류별로 훑어보기). v4 때 이 방법으로 "리모컨 없음→리모컨 품목", "H200WF실버→H200W", 포장 지시가 배송 메시지로 가는 문제를 배포 전에 잡음. 실데이터는 저장소에 넣지 않음.
- **생산 화면** (v5, `?view=line`, 모바일 위주): 탭 `오늘`(지난 예정 포함 — v6부터 **맨 위에 CJ·경동·대신·직납 칸**(`lnCount`): 송장 뽑은 건은 뽑을 때 넣은 박스 수 합, 아직 안 뽑은 건은 건수, 직납은 건수. 그 밖(직접수령·퀵·미정)은 한 줄. **"오늘 아직 만들 것" 합계는 카드 맨 아래**) · v7: **운송사 색**(`carClass` — CJ 파랑 · 경동 빨강 · 대신 초록 · 직납 갈색 · 그 밖 회색)을 위 칸·카드 위 테두리·배지(`cbadge`)·사무실 카드 배송 태그에 같이 씀. 위 칸을 누르면 그 운송사 주문만(`LN.car`), 다시 누르거나 `전체 보기`로 해제 · `다음`(내일·이번 주·이후·날짜 미정) · `만들 양`(아직 안 만든 주문의 품목 합계). 카드마다 **준비완료**·**송장부착** 버튼(직납·방문·퀵은 송장부착 대신 **출고준비** = 같은 칸). 송장부착을 켜면 준비완료도 켜지고, 준비완료를 끄면 송장부착도 꺼짐. 누른 사람 이름은 폰에 한 번 저장(`so-name`). 순서 = 안 만든 것 → 준비완료만(주황 띠) → 송장부착(흐림, 맨 아래). 화면이 켜져 있을 때만 2분마다·다시 볼 때 새로고침. **전화·주소·보내는분·원문은 서버가 아예 안 보냄**(`lineSlim_`). v9부터 받는분은 **이름만** 보내서 카드 제목을 `거래처명(받는분)`으로 표시(`lnName`, 받는분이 없거나 거래처와 같으면 거래처명만) — 같은 거래처의 직송 여러 건을 송장과 맞춰 붙이기 위해 (사용자 요청 11-18).
  - 권한(`api`): 사무실 암호가 켜져 있으면 → 사무실 암호 = 모든 기능, **생산 암호 = `LINE_FNS`(lineBoot·lineMark)만**, 그 밖엔 needPin. 사무실 암호가 꺼져 있으면 누구나 모든 기능(생산 암호 의미 없음 — 더보기에 경고 표시).
  - 사무실 화면: 카드에 `준비완료 ✓ 시각`·`송장부착 ✓ 시각`. 출하서 미리 체크 = 송장부착(출고준비)된 대기 주문(`closeChecked`; 사무실이 직접 누른 체크가 우선). 생산이 아무것도 안 누른 상태면 예전처럼 그날 송장 뽑은 것.
  - `saveOrders`는 기존 주문을 고칠 때 준비완료·송장부착 칸을 시트 값 그대로 둠(사무실이 오래된 화면으로 저장해도 생산 표시가 안 지워짐).
- **암호**: `주문_설정`의 암호가 있으면 모든 `api` 호출이 `{needPin:true}` → 화면이 물어보고 폰에 기억(`localStorage so-pin`).

### 나중 연결 (설계만 해 둠)
- **출고완료 → 재고 차감**: `주문.품목JSON`의 `name`을 `품목마스터`의 `품목ID(품명||분류)`에 맞춰 `거래로그`에 출고 줄을 **덧붙이는** 방식(재고앱 규칙). 어느 분류(완포/벌크)·어느 위치에서 뺄지 정해야 함. 한 번 뺀 주문은 `주문.재고차감` 칸에 표시해 두 번 빼지 않게.

- **사진 발주**는 읽지 못함 → `직접 입력`.
- 출고 예정은 "내일"과 "준비·입금·입고되면"만 알아봄. "다음주 목요일", "11월 말"은 적요에 남고 날짜는 오늘로 들어감 → 직접 고치기.
- 한 메시지에 주문이 둘 이상이면(빈 줄로 나눈 두 거래처) 1건으로 들어감.
- 한글 수량("세박스")·"H-10" 같은 표기는 품목으로 못 잡을 수 있음.
- 옵션 펼치기의 "온도센서"는 이름 그대로 들어감(실제 몰딩/건식 등 어떤 센서인지는 모름) → 거래처별 품목명 학습으로 바꿔 두기.
- 주문이 수천 줄로 늘면 `boot`가 느려질 수 있음 (지금은 `주문` 탭 전체를 읽고 최근 21일+대기만 보냄) → 그때 연도별 보관 탭으로 옮기기.
- 대신화물 엑셀은 원본의 줄 높이·병합을 완전히 같게 맞추지는 않았음 (열·글자·표 구조는 같음).
- 접근 제한은 암호 하나(공유). 사람별 권한·누가 고쳤는지 기록은 없음.
