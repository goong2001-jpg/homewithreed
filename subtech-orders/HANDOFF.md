## 2. 꼭 지킬 규칙

1. **재고앱을 건드리지 않는다.** `subtech-inventory/` 폴더, 브랜치 `claude/spreadsheet-accessibility-opmsi3`, 워크플로 `deploy-subtech.yml` 수정 금지.
2. **시트는 `주문`, `주문_거래처`, `주문_송장기록`, `주문_설정`, `주문_출하기록` 탭만 쓴다.** `품목마스터`는 읽기만, `거래로그`·`위치도` 등은 읽지도 쓰지도 않는다. (`Code.gs`의 `sheet_()`가 `OWN` 목록 밖의 탭을 거절함 · 테스트가 검사) 재고 연결(3단계)로 `거래로그`에 쓰게 될 때는 **사용자 승인을 따로 받는다.**
3. **새 배포 만들지 않기.** 처음 한 번(DEPLOY.md 4번) 말고는 "배포 > 새 배포" 금지 — 주소가 바뀜.
4. **버전 짝 맞추기.** `Code.gs`의 `APP_VERSION`과 `Index.html`의 `HTML_VERSION`을 같이 올린다. 다르면 워크플로가 막고 앱이 경고를 띄움.
5. **엑셀 양식은 바꾸지 않는다.** `Out.html`의 `CJ_H`·`KD_H`·`DS_H`·`RP_H`(머리줄)와 열 순서는 사무실이 쓰던 파일 그대로 (사용자 요청: "형식은 가급적 바꾸지마").
6. **실제 고객 정보를 저장소에 올리지 않는다.** 카톡 원문·엑셀 원본·주소록은 커밋 금지. 테스트 견본은 지어낸 이름·전화·주소만. (`dev/.gitignore`가 `*.xlsx`, `data*.json`, `out/` 제외)
7. **주문 탭 열 순서 바꾸지 않기** (`OH`/`OK_`). 새 열은 맨 뒤에 덧붙인다. 주문은 지우지 않고 `상태=취소`로 남긴다.
8. **`Index.html` 안에 `<` + `?` 를 붙여 쓰지 않는다** (끼워넣기 3줄 제외). Apps Script가 서버 코드로 읽어 앱이 안 열림. 테스트가 검사.
9. **새 권한(스코프)이 필요한 서비스(UrlFetchApp·DriveApp 등)를 넣지 않는다** — 웹앱이 재승인 전까지 멈춤. 지금은 스프레드시트 권한만.
10. 코드는 GitHub에서만 고친다 · 비밀값은 Secrets에만 · PR은 요청할 때만 · 푸시 후 배포 성공 확인까지가 작업 끝.
11. 변경 이력은 자동 기록(`CHANGELOG.md` 손대지 않기). 커밋 메시지 `vNN: 무엇을` + `- ` 목록. 봇 커밋이 생기므로 작업 시작·푸시 전에 `git pull --rebase origin ccr-45fa06b9-ax86xs`.
12. 사용자 응답은 **한국어, 짧게**. 결정이 필요하면 추천안을 먼저.

## 3. 구조

### 파일
| 파일 | 역할 |
|---|---|
| `Code.gs` | 서버. `doGet`, `inc`(HTML 끼워넣기), **`api(pin, fn, arg)` 하나가 입구** → `API.boot / saveOrders / setStatus / markPrinted / closeDay / reports / report / custSave / custImport / histImport / recData / setPin` |
| `Index.html` | 화면 전체(한 페이지). 아래 탭(PC는 왼쪽): 새 주문 · 주문 · 송장 · 출하서 · 더보기 |
| `Parse.html` | `OP` — 카톡 나누기(`splitMessages`, `parseOrder`, `itemParse`, `shipParse`/`shipLabel`), 거래처 찾기(`findCust`), 박스 추천(`buildRec`, `suggest`). DOM 안 씀 |
| `Out.html` | `OUT` — 엑셀 양식(`cj`, `kd`, `ds`, `report`)과 옛 엑셀 가져오기(`importBook`). DOM 안 씀 |
| `Xlsx.html` | `XL` — 라이브러리 없는 xlsx 만들기(`build`, 서식 번호 0~10)·읽기(`read`, 브라우저 `DecompressionStream`) |
| `appsscript.json` | 웹앱: `executeAs: USER_DEPLOYING`, `access: ANYONE_ANONYMOUS`, V8 |
| `dev/` | 테스트 도구(배포 안 됨): `test.js`, `mock-page.js`, `smoke.js`, `fake-gas.js`, `changelog.js` |

`Parse/Out/Xlsx.html`은 `<script>` 한 덩어리이고 `Index.html`에 `inc()`로 끼워집니다. node 테스트는 `<script>` 태그만 떼고 그대로 실행합니다.

| 탭 | 내용 |

### 핵심 흐름
- **붙여넣기** → `OP.splitMessages`(폰 내보내기 `2026년 …, 이름 : ` / PC 복사 `[이름] [오전 11:17] ` / 형식 없으면 1건) → 메시지마다 `OP.parseOrder` → 품목이 하나라도 있으면 발주로 봄 → `enrich()`가 주소록으로 빈 칸 채움 → 미리보기에서 고치고 저장. 거래처가 없는 건 기본 체크 해제.
- **배송 판단** `shipParse`: 대신 > 경동 > 직납 > 직접수령(방문) > 퀵 > 택배(=CJ) > 화물(경동/대신 선택 필요). `shipLabel`이 출하서 표기를 만듦 (택배선불 청구 / 경동택배선불 / 대신화물 / 직납 …).
- **직송 건**: 받는분 이름+주소가 따로 있고 거래처가 주소록에 있으면 보내는분 = 거래처 (CJ 파일의 와이코퍼레이션·부경테크 방식).
- **송장**: 운송별 대기·미출력 주문 → 박스 입력(크기별 여러 줄 = 엑셀에서도 여러 줄) → 엑셀/복사 → `markPrinted`(박스 저장 + 송장기록 추가).
- **박스 추천** `OP.suggest`: ①품목·수량이 똑같은 옛 주문 → 그대로 ②없으면 품목별 "박스 한 개에 담은 양"(90% 지점)으로 계산. 2025.06~ CJ 기록으로 확인했을 때 크기+수 일치 약 76%, 박스 수 일치 약 86%, 추천 없음 약 6% (앞 85%로 배우고 뒤 15%로 확인). **참고용** — 화면에 "추천 — 확인하세요" 표시.
- **출하서** `closeDay`: 체크한 주문을 출고완료(출고일=그 날짜)로 바꾸고, 그 날 출고완료 전부 + 대기 전부를 `주문_출하기록`에 저장 → 화면이 `OUT.report`로 엑셀 생성. 같은 날 다시 마감하면 그 날짜 줄만 갱신. 부자재(센서·파워코드 등, `OP.isAcc`)는 "50개"처럼 글자로 쓰고 합계에서 뺌 (원래 양식과 같음).
- **암호**: `주문_설정`의 암호가 있으면 모든 `api` 호출이 `{needPin:true}` → 화면이 물어보고 폰에 기억(`localStorage so-pin`).

### 나중 연결 (설계만 해 둠)
- **출고완료 → 재고 차감**: `주문.품목JSON`의 `name`을 `품목마스터`의 `품목ID(품명||분류)`에 맞춰 `거래로그`에 출고 줄을 **덧붙이는** 방식(재고앱 규칙). 어느 분류(완포/벌크)·어느 위치에서 뺄지 정해야 함. 한 번 뺀 주문은 `주문.재고차감` 칸에 표시해 두 번 빼지 않게.
- **주문 → 필요 자재**: 대기 주문의 품목 합계 × 재고앱 `BOM` 탭(읽기) → 부족 자재 목록.

- 한 메시지에 주문이 둘 이상이면(빈 줄로 나눈 두 거래처) 1건으로 들어감.
- 한글 수량("세박스")·"H-10" 같은 표기는 품목으로 못 잡을 수 있음.
- 주문이 수천 줄로 늘면 `boot`가 느려질 수 있음 (지금은 `주문` 탭 전체를 읽고 최근 21일+대기만 보냄) → 그때 연도별 보관 탭으로 옮기기.
- 대신화물 엑셀은 원본의 줄 높이·병합을 완전히 같게 맞추지는 않았음 (열·글자·표 구조는 같음).
- 접근 제한은 암호 하나(공유). 사람별 권한·누가 고쳤는지 기록은 없음.
